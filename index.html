1번

표지

20초슬라이드 열기 ↗

발표할 논문은 AAAI 2023에 실린 "TrOCR: Transformer-Based Optical Character Recognition with Pre-trained Models"입니다. Microsoft와 베이항 대학의 연구로, 사진 속 글자를 읽는 OCR[1]을 사전학습[2]된 Transformer[3] 두 개만으로 만든 논문입니다.
배경부터 한계까지 일곱 부분으로 진행하겠습니다.

1부. 배경

2번

글자를 읽는 AI

40초슬라이드 열기 ↗

요즘은 사진을 찍으면 글자가 바로 텍스트로 바뀝니다. 이미지 속 글자를 읽어 텍스트로 바꾸는 기술을 OCR[1], 광학 문자 인식이라고 합니다.
→ 영수증 정리, 손글씨 필기 디지털화, 간판 번역, 그리고 시험지를 찍으면 풀이를 보여 주는 앱까지 모두 이 단계를 거칩니다.
→ AI 치팅 앱도 첫 단계는 OCR입니다. 다만 TrOCR가 하는 일은 사진을 글자로 바꾸는 데까지이고, 문제를 푸는 것은 뒤에 붙는 언어모델[4]입니다. 오늘은 앞부분, AI가 글자를 어떻게 읽는지를 다룹니다.

3번

논문 정보와 연구 질문

40초슬라이드 열기 ↗

연구 질문은 CNN[5]과 RNN[6] 없이, 이미 사전학습[2]된 이미지 Transformer[3]와 텍스트 Transformer만으로 글자 인식기를 만들 수 있느냐입니다. 공식 코드와 학습된 모델이 공개돼 있어서 직접 실험도 해 봤습니다.
→ 논문이 주장하는 기여는 세 가지입니다. 두 Transformer를 이은 End-to-End 모델, 대규모 합성 데이터[7]로 사전학습한 뒤 Fine-tuning[8]하는 학습 방법, 그리고 인쇄체·손글씨·장면 글자[9]에서 당시 최고 수준의 성능입니다.
→ 범위도 분명히 하겠습니다. 입력은 이미 잘라 낸 한 줄 글자 이미지입니다. 사진 전체에서 글자 위치를 찾는 텍스트 검출[10]은 범위 밖이라고 논문이 직접 밝힙니다.

2부. 독창성

4번

기존 OCR

50초슬라이드 열기 ↗

기존 OCR[1]은 보통 부품 네 개를 이어 붙입니다. 먼저 CNN[5]이 이미지에서 특징 지도를 뽑습니다.
→ 다음으로 RNN[6], 주로 양방향 LSTM[11]이 왼쪽에서 오른쪽으로 문맥을 이어 붙이고,
→ CTC[12]가 열마다 문자를 고른 뒤 중복과 빈칸을 지워 글자열을 만듭니다.
→ 마지막으로 따로 학습한 언어모델[4]이 철자 오류를 후처리로 고칩니다.
→ 논문이 문제 삼은 부분은 이렇습니다. 이미지 이해는 CNN, 글자 생성은 RNN, 언어 지식은 별도 모델에 나눠 맡기고, 대규모 사전학습[2] 모델은 거의 쓰지 않는다는 점입니다.

5번

TrOCR의 독창성

50초슬라이드 열기 ↗

TrOCR는 이 부품들을 Transformer[3] 두 개로 바꿉니다. 이미지 쪽은 패치[13]를 입력받는 이미지 Transformer, 글자 쪽은 wordpiece[14] 단위로 한 조각씩 생성하는 텍스트 Transformer입니다. 두 쪽 모두 공개된 사전학습[2] 가중치에서 시작하고, 언어 지식이 디코더 안에 들어 있어서 외부 언어모델[4]을 따로 붙이지 않습니다.
→ 근거가 되는 비교입니다. 사전학습 단계 없이 SROIE[15] 영수증 데이터만으로 학습했을 때, 같은 RoBERTa-Large 디코더라도 CNN[5]인 ResNet50 인코더는 F1[16] 71.83, 사전학습된 BEiT[17] 인코더는 79.36이었습니다.

3부. 모델

6번

모델 전체 구조

1분슬라이드 열기 ↗

입력은 잘라 낸 한 줄 이미지입니다. 384×384로 크기를 맞춘 뒤 16×16 패치[13] 576개로 자릅니다.
→ 패치들은 Encoder로 들어갑니다. Self-Attention[18]과 Feed Forward[19] 층을 여러 번 쌓은 이미지 Transformer[3]이고, BEiT[17]나 DeiT[20]로 초기화합니다.
→ Decoder는 텍스트 Transformer입니다. Masked Self-Attention[21], Cross-Attention[22], Feed Forward로 이루어지고, Cross-Attention으로 Encoder가 만든 이미지 특징을 봅니다. RoBERTa[23]나 MiniLM[24]으로 초기화합니다.
→ Decoder는 토큰을 하나 만들 때마다 그 토큰을 다시 입력으로 넣어 다음 토큰을 만듭니다. 이것을 자기회귀[25]라고 하고, [EOS]가 나오면 멈춥니다.
→ 크기는 세 가지입니다. Small은 6,200만, Base는 3억 3,400만, Large는 5억 5,800만 파라미터입니다.

7번

Encoder

1분 10초슬라이드 열기 ↗

Encoder를 단계별로 보겠습니다. 입력은 글자가 들어 있는 한 줄 이미지입니다.
→ 먼저 384×384 정사각형으로 크기를 바꿉니다. 비율을 무시하고 늘리기 때문에 글자가 세로로 길쭉해집니다.
→ 이것을 16×16 픽셀 패치[13]로 자릅니다. 384를 16으로 나누면 24라서 패치는 24×24, 576개입니다. ViT[26]처럼 패치 하나를 문장의 단어 하나처럼 다룹니다.
→ 패치를 한 줄로 펼쳐 각각 벡터로 바꾸고, 맨 앞에 [CLS] 토큰[27]을 붙인 뒤 순서를 알 수 있게 위치 임베딩[28]을 더합니다. 화면에는 13번째 줄 패치 24개만 보였고, 실제로는 576개가 한 줄로 들어갑니다.
→ 그 다음 Self-Attention[18]으로 모든 패치가 서로를 참고해서 문맥이 담긴 특징 벡터가 됩니다. 연결선 굵기는 개념도이고 실제 모델에서 뽑은 Attention 값은 아닙니다.

8번

Decoder

1분 10초슬라이드 열기 ↗

Decoder는 글자를 한 조각씩 씁니다. 시작 토큰[29] [BOS]에서 출발합니다. 자동 재생 버튼으로 보여 드려도 됩니다.
→ 첫 토큰으로 Reading이 가장 높은 확률을 받아 선택됩니다. 이때 Cross-Attention[22]으로 이미지의 해당 부분을 참고합니다.
→ 선택한 토큰은 다음 단계의 입력이 됩니다. 다음은 text,
→ from,
→ pix처럼 한 단어가 여러 조각으로 나뉘기도 합니다. 이 조각 단위를 wordpiece[14]라고 합니다.
→ 이어서 els,
→ 끝 토큰 [EOS]가 가장 높으면 생성을 멈춥니다. 화면의 토큰 분할과 확률은 설명용 예시이고, 실제 추론은 후보를 10개씩 유지하는 빔 서치[30]를 씁니다.

4부. 학습

9번

사전학습과 Fine-tuning

1분슬라이드 열기 ↗

TrOCR는 처음부터 학습하지 않습니다. 이미지로 사전학습[2]된 BEiT[17]·DeiT[20]와 텍스트로 사전학습된 RoBERTa[23]·MiniLM[24] 가중치로 시작합니다.
→ 1단계 사전학습은 공개 PDF 문서 200만 페이지에서 만든 인쇄체 텍스트 줄 6억 8,400만 개로 합니다.
→ 2단계는 과제에 맞춘 합성 데이터[7]입니다. 손글씨 폰트 5,427종으로 만든 손글씨 1,790만 줄, 영수증을 포함한 인쇄체 330만 줄, 장면 글자[9]용 합성 데이터 약 1,600만 장입니다.
→ 마지막으로 영수증 SROIE[15], 손글씨 IAM[31], 장면 글자 벤치마크에 각각 Fine-tuning[8]합니다.
→ 데이터 증강[32]도 씁니다. 인쇄체와 손글씨는 원본과 회전, 블러, 팽창, 침식, 축소, 밑줄 여섯 가지 변환 중 하나를 같은 확률로 고릅니다. 화면의 이미지는 브라우저에서 흉내 낸 예시입니다.

10번

학습과 손실함수

1분슬라이드 열기 ↗

학습할 때는 teacher forcing[33]을 씁니다. 정답을 한 칸 밀어서 디코더 입력으로 넣고, 위치마다 다음 정답 토큰을 맞히게 합니다. 입력이 [BOS][29]면 TOTAL을, TOTAL이면 12를 맞혀야 합니다.
→ 손실은 정답 토큰 확률에 로그를 씌우고 부호를 바꾼 교차 엔트로피[34]입니다. 세 번째 점의 확률이 0.48로 낮아서 손실이 0.734로 가장 크고, 평균 손실은 0.214입니다. 확률 값은 설명용 예시입니다.
→ 오른쪽 그래프처럼 정답 확률이 1이면 손실이 0이고, 0에 가까워질수록 급하게 커집니다. 슬라이더로 확률을 낮춰 보면 손실이 빠르게 늘어납니다. 그래서 틀린 토큰을 강하게 고치는 방향으로 학습됩니다.

5부. 평가·결과

11번

평가 지표 CER·WER

1분슬라이드 열기 ↗

CER[35]은 문자 오류율입니다. 정답을 인식 결과로 바꾸는 데 필요한 바뀐 글자 S, 빠진 글자 D, 끼어든 글자 I의 수를 정답 글자 수 N으로 나눕니다.
→ 예를 들어 정답 TOTAL 12.50 CASH를 T0TAL 12.5 CASHH로 읽으면, O가 0으로 바뀌고, 0이 빠지고, H가 끼어들어 오류가 3개입니다. 정답이 16글자라 CER은 18.8%입니다. 그런데 WER[36]은 세 단어가 모두 틀려서 100%입니다. 글자 하나만 틀려도 단어 전체가 오류가 되기 때문입니다. 두 지표 모두 낮을수록 좋습니다.
→ 논문은 데이터마다 지표가 다릅니다. IAM[31]은 대소문자를 구분한 CER, SROIE[15]는 단어 단위 F1[16], 장면 글자[9]는 단어 정확도[37]를 씁니다.

12번

원논문 실험 결과

1분 20초슬라이드 열기 ↗

왼쪽은 SROIE[15]에서 학습 설정을 하나씩 더한 결과입니다. 처음부터 학습하면 F1[16]이 38.24이고, 사전학습[2] 모델로 초기화하면 72.75, 데이터 증강[32]을 더하면 82.30, 1단계 사전학습을 더하면 95.48, 2단계까지 하면 95.84입니다.
→ 노란 칸이 단계별 차이입니다. 다만 앞 단계를 모두 포함한 누적 결과라서 각 기법의 독립적인 효과로 보면 안 됩니다. 그래도 구조는 그대로 두고 사전학습과 데이터 설계만으로 성능이 크게 달라졌다는 점이 머신러닝 관점에서 가장 중요한 결과입니다.
→ IAM[31] 손글씨에서는 TrOCR-Large가 CER[35] 2.89%입니다. 표에서 더 낮은 Diaz et al.의 2.75%는 비공개 내부 데이터와 외부 언어모델[4]을 써서 조건이 다릅니다. 합성 데이터[7]와 IAM만 쓴 방법 중에서는 TrOCR-Large가 가장 낮습니다.
→ SROIE 영수증에서는 TrOCR-Large가 F1 96.58로 대회 1위 H&H Lab의 96.43보다 높았고, 오픈소스 OCR[1]인 Tesseract[38]는 54.57이었습니다.

6부. 자체 실험

13번

자체 OCR 비교 실험

1분슬라이드 열기 ↗

공개된 microsoft/trocr-small-printed 모델과 오픈소스 OCR[1]인 Tesseract[38]를 같은 이미지 【○장】으로 비교했습니다. 【이미지를 어떻게 모았는지, 디코딩 설정 한 줄】. 빨간 표시가 틀린 글자, 꺾쇠가 빠진 글자입니다.
→ 전체 CER[35]은 TrOCR 【○○%】, Tesseract 【○○%】입니다. 【차이가 가장 컸던 이미지와 그 이유 한두 문장】.

14번

이미지 품질에 따른 변화

1분슬라이드 열기 ↗

이번에는 같은 문장 이미지에 흐림, 회전, 잡음을 각각 다섯 단계로 넣고 측정했습니다. 탭으로 조건을 고르고 슬라이더로 강도를 바꾸면, 왼쪽에는 그 조건의 이미지와 실제 인식 결과, 오른쪽에는 강도별 CER[35]이 나옵니다.
논문이 학습할 때 회전과 블러를 증강에 썼기 때문에 약한 변형에는 버틸 것으로 예상했습니다. 【실제 결과: 어느 조건, 어느 강도부터 CER이 올라갔는지】.

7부. 한계

15번

한계와 AI 치팅과의 관계

1분 10초슬라이드 열기 ↗

한계는 네 가지입니다. 첫째, 글자 위치는 찾지 못합니다. 시험지 한 장을 읽으려면 앞에 검출 모델이 따로 필요합니다. 둘째, 크고 느립니다. IAM[31] 2,915문장 기준으로 Small은 초당 8.37문장, Base는 4.60문장을 처리합니다. 셋째, 공개 모델은 영어 중심이라 한국어는 데이터와 토크나이저부터 다시 학습해야 합니다. 넷째, 장면 글자[9]에서는 정답 표기에 없는 기호를 출력해 오답 처리되는 경우를 논문이 보고합니다.
→ 처음의 AI 치팅 이야기로 돌아가면, 사진 한 장이 풀이가 되기까지는 검출, 인식, 언어모델[4], 답의 네 단계가 있고 TrOCR는 두 번째 인식 단계만 맡습니다.
→ TrOCR는 읽기만 하고, 정답을 추론하는 것은 언어모델입니다. 다만 OCR[1]이 좋아질수록 종이 시험도 쉽게 디지털 입력이 된다는 점에서 연결됩니다. 이런 환경에서 평가가 무엇을 측정해야 할지는 같이 생각해 볼 질문입니다.

16번

정리

40초슬라이드 열기 ↗

TrOCR는 한 줄 이미지를 패치[13]로 나누고, Encoder가 이미지 특징을 만들고, Decoder가 토큰을 하나씩 생성해서 글자를 읽습니다.
→ 구조 면에서는 CNN[5]·RNN[6] 없이 사전학습[2] Transformer[3] 두 개로 End-to-End OCR[1]을 만들었고, 학습 면에서는 같은 구조라도 사전학습과 데이터 증강[32]에 따라 SROIE[15] F1[16]이 38.24에서 95.84로 달라졌습니다. 그리고 TrOCR는 잘라 낸 글자를 읽는 모델이고, 검출과 문제 풀이는 다른 모델의 몫입니다.

논문 실험 상세

질문이 나오면 참고. 숫자는 arXiv:2109.10282v5 기준.

SROIE 영수증 (인쇄체)

  • 데이터: ICDAR 2019 영수증 대회 Task 2. 영수증에서 잘라 낸 글자 줄을 인식
  • 지표: 단어 단위 정밀도[16]·재현율·F1. 정답에 같은 단어가 여러 번 있으면 예측에도 그만큼 있어야 맞음
  • 결과 (F1): TrOCR-Small 95.82, Base 96.34, Large 96.58. 대회 1위 H&H Lab 96.43, MSOLab 94.82, CLOVA OCR[1] 94.59, Tesseract[38] 54.57, CRNN 36.09
  • 인코더·디코더 조합 비교 (Table 1, SROIE[15]만으로 학습, F1): RoBERTa-Base 디코더일 때 ResNet50 67.02, DeiT-Base 69.17, BEiT-Base 76.31 / RoBERTa-Large 디코더일 때 71.83, 76.78, 79.36

IAM 손글씨

  • 데이터: 영어 손글씨 문장 줄 이미지
  • 지표: 대소문자를 구분한 CER[35]
  • 결과: TrOCR-Small 4.22, Base 3.42, Large 2.89. 모두 합성 데이터[7] + IAM[31]만 쓰고 외부 언어모델[4] 없음
  • 비교: Kang et al. 2020 4.67, Michael et al. 2019 4.87, Bluche & Messina 2017 3.2(외부 언어모델 사용), Diaz et al. 2021 2.75(비공개 내부 데이터 + 외부 언어모델)

장면 글자 (Scene Text)

  • 데이터: 간판·거리 사진 속 단어 이미지 벤치마크 8개 (IIIT5K, SVT, IC13 두 종류, IC15 두 종류, SVTP, CT80)
  • 지표: 단어 정확도[37]. 영문 소문자와 숫자 36자만 남기고 비교
  • 2단계 사전학습[2]: 합성 데이터[7] MJSynth + SynthText 약 1,600만 장, 증강은 RandAugment
  • 결과: Table 6. 발표 전에 원문 표에서 벤치마크별 숫자를 직접 확인할 것
  • 논문이 언급한 오류: 장면 사진의 기호가 정답에는 없어서 출력이 일관되지 않음

속도와 크기 (Table 5)

  • 측정: IAM[31] 테스트 2,915문장
  • Small 62M: 348.4초, 초당 8.37문장
  • Base 334M: 633.7초, 초당 4.60문장
  • Large 558M: 666.8초, 초당 4.37문장
  • Base와 Large는 속도 차이가 크지 않고, Small은 약 2배 빠름

학습 설정

  • 입력 384×384, 패치[13] 16×16, 위치 임베딩[28]은 학습되는 1차원 임베딩, [CLS] 토큰[27] 유지 (DeiT[20]는 증류 토큰도 유지)
  • 토크나이저: Fairseq의 BPE와 SentencePiece (wordpiece[14] 단위)
  • 손실: 교차 엔트로피[34]. 정답을 [BOS][29]로 한 칸 민 것을 디코더 입력으로, [EOS]로 끝나는 정답을 출력 목표로
  • 배치 2,048, 학습률 5e-5, 빔 크기 10. 사전학습[2]은 V100 32대, Fine-tuning[8]은 V100 8대

예상 질문과 답

  • 왜 이미지를 384×384로 늘리나요? 비율이 깨지지 않나요?
  • 논문이 이유를 따로 밝히지는 않습니다. 사전학습[2]된 BEiT[17]·DeiT[20] 인코더가 고정 크기 입력과 고정 길이 위치 임베딩[28]을 쓰기 때문으로 볼 수 있습니다. 글자가 길쭉해져도 학습 데이터 전체가 같은 방식으로 늘어나서 모델이 그 모양에 적응합니다.
  • CTC[12] 방식과 무엇이 다른가요?
  • CTC는 열마다 문자를 따로 예측하고 합칩니다. TrOCR 디코더는 앞에서 쓴 토큰을 조건으로 다음 토큰을 예측하기 때문에, 언어 지식이 예측 안에 들어갑니다.
  • 왜 외부 언어모델[4]이 필요 없나요?
  • 디코더를 RoBERTa[23]나 MiniLM[24]으로 초기화해서, 텍스트로 사전학습한 언어 지식을 처음부터 갖고 있기 때문입니다.
  • 시험지 전체 사진을 넣으면 읽을 수 있나요?
  • 아니요. 한 줄로 잘라 낸 이미지를 입력으로 받습니다. 시험지 전체를 읽으려면 글자 위치를 찾는 검출 모델이 앞에 필요합니다.
  • 한국어도 읽을 수 있나요?
  • 공개 모델은 영어 데이터와 영어 토크나이저로 학습돼 있어서 바로는 어렵습니다. 한국어 데이터와 토크나이저로 다시 학습해야 합니다.
  • 화면의 확률과 Attention은 실제 모델 값인가요?
  • 아니요. 7·8·10번의 확률과 연결선은 설명용 개념도이고 화면에 그렇게 표시했습니다. 실제 값은 12번 이후의 논문 수치와 13·14번 실험 결과입니다.
  • 빔 서치[30]는 왜 쓰나요?
  • 매번 가장 높은 토큰 하나만 고르면 초반 실수를 되돌릴 수 없습니다. 후보 여러 개를 동시에 유지하다가 전체 확률이 가장 높은 문장을 고릅니다. 논문은 빔 크기 10을 씁니다.
  • TrOCR-Large가 IAM[31]에서 최고라고 할 수 있나요?
  • 표의 최저값은 Diaz et al. 2.75%지만 비공개 내부 데이터와 외부 언어모델을 썼습니다. 합성 데이터[7]와 IAM만 쓴 조건에서는 TrOCR-Large 2.89%가 가장 낮습니다.
  • 12번 그래프의 단계별 차이가 각 기법의 효과인가요?
  • 아닙니다. 앞 단계를 모두 포함한 누적 결과라서, 예를 들어 데이터 증강[32]만의 효과로 9.55를 해석할 수 없습니다. 순서를 바꾸면 차이도 달라질 수 있습니다.
  • 자체 실험에 small-printed 모델을 쓴 이유는?
  • 가장 작은 공개 모델이라 노트북 CPU로도 돌릴 수 있고, 실험 이미지가 인쇄체라서 인쇄체용 모델을 골랐습니다. 손글씨는 trocr-base-handwritten 같은 손글씨용 모델이 따로 있습니다.
  • Transformer[3]가 CNN[5]보다 항상 좋은가요?
  • 이 논문의 Table 1 조건, 즉 SROIE[15]만으로 학습한 비교에서는 사전학습된 BEiT가 ResNet50보다 높았습니다. 일반적인 결론으로 넓히지는 않습니다.
