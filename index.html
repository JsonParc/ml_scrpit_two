TrOCR 발표 대본

발표 사이트 슬라이드 순서와 같다. 본편 21장 + 질문 대비 부록 2장. 예상 시간: 본편 약 15분.
→ 표시는 그 자리에서 → 키를 누르면 슬라이드의 다음 단계가 나온다는 뜻. 마지막 단계 뒤에 → 키를 누르면 다음 슬라이드로 넘어간다.
더 줄여야 하면: 5번은 표만, 10번은 앞의 두 이유만, 13번 슬라이더 시연은 생략 가능. 부록은 질문 대응용.
용어 설명은 용어정리.txt 참고.

숫자 출처

  • 논문 수치: Li et al., arXiv:2109.10282v5 (Table 1·2·3·4·5와 본문). 발표 전에 AAAI 2023 판과 대조
  • 9·13번 슬라이드의 확률 값, 8번의 Attention 연결선: 설명용 예시 (화면에 "개념도" 표시)
  • 18·19번 자체 실험: Tesseract는 실측(Tesseract 5.5.0, --psm 7). TrOCR는 측정 후 반영 (site/index.html 안의 window.EXP)

파란 [번호]를 누르면 용어 설명이 뜹니다. 각 구간 오른쪽 위 "슬라이드 열기"는 해당 슬라이드로 이동합니다.

1번

표지

20초슬라이드 열기 ↗

발표할 논문은 AAAI 2023에 실린 "TrOCR: Transformer-Based Optical Character Recognition with Pre-trained Models"입니다. 사전학습[1]된 Transformer[2]로 사진 속 글자를 읽는 OCR[3] 모델을 만든 연구입니다.
논문 선택 이유부터 한계와 극복 아이디어까지 여섯 부분으로 진행하겠습니다.

개요

2번

논문 요약

40초슬라이드 열기 ↗

한 문장으로 요약하면, 사전학습[1]된 이미지 Transformer[2]와 텍스트 Transformer를 연결해서 잘라 낸 한 줄 글자 이미지를 텍스트로 바꾸는 모델을 만들고, 대규모 합성 데이터[4]로 사전학습한 뒤 인쇄체·손글씨·장면 글자[5]에서 평가한 연구입니다.
→ 질문은 CNN[6]과 RNN[7] 없이 사전학습 Transformer만으로 글자 인식이 되느냐이고, 모델은 인코더-디코더[8] Transformer, 학습은 2단계 사전학습과 Fine-tuning[9], 평가는 세 종류 벤치마크입니다.
→ 머신러닝 핵심 개념은 이 다섯 가지이고, 발표에서 이 순서대로 나옵니다.

1부. 논문 선택 이유

3번

논문을 고른 이유

40초슬라이드 열기 ↗

시험지를 찍으면 풀이를 보여 주는 AI 앱, 이른바 AI 치팅이 화제가 된 것을 봤습니다.
→ 이런 앱은 먼저 사진 속 글자를 텍스트로 바꿔야 하는데, 이 첫 단계가 어떻게 동작하는지 궁금해졌습니다.
→ 관련 논문을 찾다가 사전학습[1] Transformer[2]로 OCR[3]을 만든 TrOCR를 알게 됐습니다.
→ 읽어 보니 수업 내용과 연결되는 부분이 많아서 골랐습니다.
→ Transformer와 Attention, 전이학습[10], 교차 엔트로피[11] 손실, 데이터 증강[12], 평가 지표가 모두 나옵니다. 마지막 줄의 이미지 처리는 한계 부분에서 연결하겠습니다.

2부. 독창성

4번

배경

50초슬라이드 열기 ↗

사진에서 글자를 읽는 과정은 보통 이렇습니다. 사진에서 글자 위치를 찾고, 찾은 부분을 글자로 읽고, 필요하면 언어모델[13]이 그 텍스트로 문제를 풉니다.
→ OCR[3]은 글자 영역을 찾는 검출과, 잘라 낸 영역을 읽는 인식 두 단계로 나뉩니다. TrOCR는 이 중 인식만 다루고, 검출은 논문 범위 밖입니다.
→ 기존 인식 방법은 CNN[6]으로 이미지 특징을 뽑고, RNN[7]으로 문맥을 처리하고, CTC[14]로 글자열을 출력합니다. 정확도를 높이려고 외부 언어모델로 후처리하기도 합니다.
→ 그래서 논문은 CNN과 RNN 없이, 사전학습[1]된 Transformer[2]만으로 글자를 인식할 수 있는지를 묻습니다.

5번

기존 방법과 비교

50초슬라이드 열기 ↗

기존 방법은 CNN[6], RNN[7], CTC[14], 외부 언어모델[13] 네 부품을 이어 붙입니다.
→ TrOCR는 이것을 이미지 Transformer[2] 인코더와 텍스트 Transformer 디코더 두 개로 바꿉니다.
→ 차이를 정리하면, 이미지는 CNN 대신 16×16 패치[15]를 입력받는 Transformer가 보고, 글자는 RNN과 CTC 대신 단어 조각 단위로 한 개씩 생성합니다. 시작 가중치는 공개된 사전학습[1] 모델에서 가져오고, 언어 지식이 디코더 안에 있어서 외부 언어모델을 붙이지 않습니다.

6번

독창성

50초슬라이드 열기 ↗

독창성은 네 가지입니다. 첫째, 사전학습[1]된 Transformer[2] 두 개만으로 구성했습니다. 논문은 사전학습된 이미지·텍스트 Transformer를 함께 쓴 첫 OCR[3] 연구라고 주장합니다.
→ 둘째, 외부 언어모델[13]이 없습니다. 디코더를 텍스트 사전학습 모델로 초기화해서 언어 지식을 이미 갖고 있습니다.
→ 셋째, 데이터 규모입니다. 1단계에서 인쇄체 텍스트 줄 6억 8,400만 개로 사전학습하고, 2단계에서 과제별 합성 데이터[4]로 다시 학습합니다.
→ 넷째, 구조를 바꾸지 않고 Fine-tuning[9]만으로 인쇄체, 손글씨, 장면 글자[5]에 모두 적용합니다.

3부. 모델

7번

TrOCR 구조

1분슬라이드 열기 ↗

입력은 잘라 낸 한 줄 이미지입니다. 384×384로 크기를 맞춘 뒤 16×16 패치[15] 576개로 자릅니다.
→ 패치들은 인코더로 들어갑니다. Self-Attention[16]과 Feed Forward[17] 층을 여러 번 쌓은 이미지 Transformer[2]이고, BEiT[18]나 DeiT[19]로 초기화합니다.
→ 디코더는 텍스트 Transformer입니다. Masked Self-Attention[20], Cross-Attention[21], Feed Forward로 이루어지고, Cross-Attention으로 인코더가 만든 이미지 특징을 봅니다. RoBERTa[22]나 MiniLM[23]으로 초기화합니다.
→ 디코더는 토큰을 하나 만들 때마다 그 토큰을 다시 입력으로 넣어 다음 토큰을 만듭니다. 이것을 자기회귀[24]라고 하고, [EOS]가 나오면 멈춥니다.
→ 크기는 세 가지입니다. Small은 6,200만, Base는 3억 3,400만, Large는 5억 5,800만 파라미터입니다.

8번

인코더

1분슬라이드 열기 ↗

인코더를 단계별로 보겠습니다. 입력은 글자가 들어 있는 한 줄 이미지입니다.
→ 먼저 384×384 정사각형으로 바꿉니다. 비율을 무시하고 늘리기 때문에 글자가 세로로 길쭉해집니다.
→ 이것을 16×16 픽셀 패치[15]로 자릅니다. 384를 16으로 나누면 24라서 패치는 24×24, 576개입니다. ViT[25]처럼 패치 하나를 문장의 단어 하나처럼 다룹니다.
→ 패치를 펼쳐 벡터로 바꾸고, 맨 앞에 [CLS] 토큰[26]을 붙인 뒤 위치 임베딩[27]을 더합니다. 화면은 13번째 줄 24개만 보여 준 것이고, 실제로는 576개가 한 줄로 들어갑니다.
→ 그 다음 Self-Attention[16]으로 모든 패치가 서로를 참고해서 문맥이 담긴 특징 벡터가 됩니다. 연결선 굵기는 개념도이고 실제 Attention 값은 아닙니다.

9번

디코더

1분슬라이드 열기 ↗

디코더는 글자를 한 조각씩 생성합니다. 시작 토큰[28] [BOS]에서 출발합니다. 자동 재생 버튼으로 보여 드려도 됩니다.
→ 첫 토큰으로 Reading이 가장 높은 확률을 받아 선택됩니다. 이때 Cross-Attention[21]으로 이미지의 해당 부분을 참고합니다.
→ 선택한 토큰은 다음 단계의 입력이 됩니다. 다음은 text,
→ from,
→ pix처럼 한 단어가 여러 조각으로 나뉘기도 합니다. 이 조각 단위를 wordpiece[29]라고 합니다.
→ 이어서 els,
→ 끝 토큰 [EOS]가 가장 높으면 생성을 멈춥니다. 토큰 분할과 확률은 설명용 예시이고, 실제 추론은 후보 10개를 유지하는 빔 서치[30]를 씁니다.

10번

이 모델을 사용한 이유

50초슬라이드 열기 ↗

첫째는 전이학습[10]입니다. 이미지와 텍스트를 각각 대규모 데이터로 학습한 가중치를 그대로 가져옵니다. SROIE[31]에서 처음부터 학습하면 F1[32]이 38.24인데, 사전학습[1] 모델로 초기화하면 72.75입니다. 둘째, Self-Attention[16]은 모든 패치[15]가 한 번에 서로를 참고해서 줄 전체의 정보를 반영합니다.
→ 셋째, 자기회귀[24] 디코더는 앞에서 생성한 토큰을 보고 다음 토큰을 예측하기 때문에 언어 지식이 예측에 들어갑니다. 넷째, 단어 조각 단위로 출력해서 어휘에 없는 단어도 표현할 수 있습니다.
→ 오른쪽은 사전학습 단계 없이 SROIE만으로 학습한 인코더 비교입니다. 같은 RoBERTa-Large 디코더에서 CNN[6]인 ResNet50은 71.83, 사전학습된 BEiT[18]는 79.36으로 Transformer[2] 인코더가 더 높았습니다.

4부. 파이프라인

11번

학습 파이프라인

1분슬라이드 열기 ↗

학습은 네 단계입니다. 공개된 사전학습[1] 가중치로 초기화하고, 인쇄체 6억 8,400만 줄로 1단계 사전학습, 과제별 합성 데이터[4]로 2단계 사전학습, 마지막으로 벤치마크별로 Fine-tuning[9]한 뒤 평가합니다.
→ 각 단계 안에서는 같은 과정을 반복합니다. 데이터를 증강하고, 순전파로 토큰별 확률을 구하고, 교차 엔트로피[11] 손실을 계산하고, 역전파로 인코더와 디코더를 함께 갱신합니다.
→ 파라미터를 갱신한 뒤 다음 배치로 반복합니다.
→ 설정은 입력 384×384, 배치 2,048, 학습률 5e-5이고, 추론은 빔 크기 10의 빔 서치[30]입니다.

12번

사전학습 데이터와 데이터 증강

40초슬라이드 열기 ↗

1단계는 공개 PDF 200만 페이지에서 만든 인쇄체 6억 8,400만 줄입니다. 2단계는 손글씨 폰트 5,427종으로 합성한 손글씨 1,790만 줄, 실제 영수증을 포함한 인쇄체 330만 줄, 장면 글자[5] 합성 데이터[4] 약 1,600만 장입니다.
→ 인쇄체와 손글씨는 원본과 회전, 블러, 팽창, 침식, 축소, 밑줄 여섯 가지 변환 중 하나를 같은 확률로 골라 증강합니다. 화면의 이미지는 브라우저에서 재현한 예시입니다.

13번

손실함수

50초슬라이드 열기 ↗

학습할 때는 정답을 한 칸 밀어서 디코더 입력으로 넣습니다. 이것을 teacher forcing[33]이라고 합니다. 입력이 [BOS][28]면 TOTAL을, TOTAL이면 12를 맞혀야 합니다.
→ 손실은 정답 토큰 확률에 로그를 씌우고 부호를 바꾼 교차 엔트로피[11]입니다. 세 번째 점의 확률이 0.48로 낮아서 손실이 0.734로 가장 크고, 평균은 0.214입니다. 확률 값은 설명용 예시입니다.
→ 정답 확률이 1이면 손실이 0이고, 0에 가까워질수록 급하게 커집니다. 슬라이더로 확률을 낮추면 손실이 빠르게 늘어납니다.

5부. 결과

14번

평가 방법

50초슬라이드 열기 ↗

평가는 세 종류 데이터로 합니다. 영수증 SROIE[31]는 단어 단위 F1[32], 손글씨 IAM[34]은 문자 오류율[35] CER, 장면 글자[5]는 단어 정확도[36]입니다.
→ CER은 정답을 인식 결과로 바꾸는 데 필요한 바뀐 글자, 빠진 글자, 끼어든 글자 수를 정답 글자 수로 나눈 값입니다. TOTAL 12.50 CASH를 T0TAL 12.5 CASHH로 읽으면 오류가 3개라서 CER은 18.8%입니다.
→ 그런데 단어 오류율[37] WER은 세 단어가 모두 틀려서 100%입니다. 글자 하나만 틀려도 단어 전체가 오류가 되기 때문입니다. 두 지표 모두 낮을수록 좋습니다.

15번

사전학습과 데이터 증강의 효과

50초슬라이드 열기 ↗

SROIE[31]에서 학습 설정을 하나씩 더한 결과입니다. 처음부터 학습하면 F1[32] 38.24, 사전학습[1] 모델로 초기화하면 72.75, 데이터 증강[12]을 더하면 82.30, 1단계 사전학습 95.48, 2단계까지 하면 95.84입니다.
→ 단계별 차이는 오른쪽과 같습니다. 다만 앞 단계를 모두 포함한 누적 결과라서 각 기법의 독립적인 효과로 보면 안 됩니다. 구조는 그대로 두고 사전학습과 데이터 설계만으로 성능이 크게 달라졌다는 점이 핵심입니다.

16번

벤치마크 결과

IAM[34] 손글씨에서는 TrOCR-Large가 CER[35] 2.89%입니다. 맨 아래 Diaz et al.의 2.75%는 비공개 내부 데이터와 외부 언어모델[13]을 써서 조건이 다릅니다. 합성 데이터[4]와 IAM만 쓴 방법 중에서는 TrOCR-Large가 가장 낮습니다.

이미지 품질에 따른 인식 변화

TOTAL 12.50 한 장에 흐림, 회전, 잡음을 각각 다섯 단계로 넣고 측정했습니다. 탭으로 조건을 고르고 슬라이더로 강도를 바꾸면 해당 이미지와 인식 결과, 강도별 CER[35]이 나옵니다.

공개 모델로 직접 비교

공개 모델로 직접 해 본 비교입니다. 합성 인쇄체 한 줄 이미지 8장을 Tesseract[38]와 TrOCR로 읽었습니다. 대소문자, 공백, 구두점을 그대로 비교했습니다.

정리

40초슬라이드 열기 ↗

문제는 기존 OCR[3]이 CNN[6], RNN[7], 외부 언어모델[13]을 따로 설계하고 대규모 사전학습[1] 모델을 거의 쓰지 않는다는 점이었습니다.
→ 방법은 사전학습된 이미지 Transformer[2]와 텍스트 Transformer를 인코더-디코더[8]로 연결하고, 2단계 합성 데이터[4] 사전학습 후 Fine-tuning[9]하는 것입니다.
→ 결과는 SROIE[31] F1[32] 96.58, IAM[34] CER[35] 2.89이고, 사전학습과 증강에 따라 SROIE F1이 38.24에서 95.84로 달라졌습니다.
→ 의의는 구조를 바꾸지 않고 전이학습[10]만으로 세 종류 글자를 인식했다는 점입니다. 검출과 문제 풀이는 별도 모델의 역할입니다.

SROIE 영수증 (인쇄체)

  • 데이터: ICDAR 2019 영수증 대회 Task 2. 영수증에서 잘라 낸 글자 줄을 인식
  • 지표: 단어 단위 정밀도[32]·재현율·F1. 정답에 같은 단어가 여러 번 있으면 예측에도 그만큼 있어야 맞음
  • 결과 (F1): TrOCR-Small 95.82, Base 96.34, Large 96.58. 대회 1위 H&H Lab 96.43, MSOLab 94.82, CLOVA OCR[3] 94.59, Tesseract[38] 54.57, CRNN 36.09
  • 인코더·디코더 조합 비교 (Table 1, SROIE[31]만으로 학습, F1): RoBERTa-Base 디코더일 때 ResNet50 67.02, DeiT-Base 69.17, BEiT-Base 76.31 / RoBERTa-Large 디코더일 때 71.83, 76.78, 79.36

IAM 손글씨

  • 데이터: 영어 손글씨 문장 줄 이미지
  • 지표: 대소문자를 구분한 CER[35]
  • 결과: TrOCR-Small 4.22, Base 3.42, Large 2.89. 모두 합성 데이터[4] + IAM[34]만 쓰고 외부 언어모델[13] 없음
  • 비교: Kang et al. 2020 4.67, Michael et al. 2019 4.87, Bluche & Messina 2017 3.2(외부 언어모델 사용), Diaz et al. 2021 2.75(비공개 내부 데이터 + 외부 언어모델)

장면 글자 (Scene Text)

  • 데이터: 간판·거리 사진 속 단어 이미지 벤치마크 8개 (IIIT5K, SVT, IC13 두 종류, IC15 두 종류, SVTP, CT80)
  • 지표: 단어 정확도[36]. 영문 소문자와 숫자 36자만 남기고 비교
  • 2단계 사전학습[1]: 합성 데이터[4] MJSynth + SynthText 약 1,600만 장, 증강은 RandAugment
  • 결과: Table 6. 발표 전에 원문 표에서 벤치마크별 숫자를 직접 확인할 것
  • 논문이 언급한 오류: 장면 사진의 기호가 정답에는 없어서 출력이 일관되지 않음

학습 설정

  • 입력 384×384, 패치[15] 16×16, 위치 임베딩[27]은 학습되는 1차원 임베딩, [CLS] 토큰[26] 유지 (DeiT[19]는 증류 토큰도 유지)
  • 토크나이저: Fairseq의 BPE와 SentencePiece (wordpiece[29] 단위)
  • 손실: 교차 엔트로피[11]. 정답을 [BOS][28]로 한 칸 민 것을 디코더 입력으로, [EOS]로 끝나는 정답을 출력 목표로
  • 배치 2,048, 학습률 5e-5, 빔 크기 10. 사전학습[1]은 V100 32대, Fine-tuning[9]은 V100 8대

자체 실험 설정

  • 이미지: 합성 인쇄체 한 줄 8장 + 품질 변화 15장(정답 "TOTAL 12.50"에 흐림·회전·잡음 각 5단계)
  • 모델: Tesseract[38] 5.5.0 (--psm 7), microsoft/trocr-small-printed (탐욕적 디코딩[40], 재학습 없음)
  • 지표: 대소문자·공백·구두점을 그대로 둔 편집 거리[41] 기준 CER[35], WER[37]. 전체 값은 편집 횟수 합 ÷ 정답 글자 수 합
  • 한계: 8장의 작은 합성 데이터[4], 품질 변화 15장은 같은 문장의 변형이라 독립 표본이 아님. 논문 벤치마크와 직접 비교하지 않음

예상 질문과 답

  • 왜 이미지를 384×384로 늘리나요? 비율이 깨지지 않나요?
  • 논문이 이유를 따로 밝히지는 않습니다. 사전학습[1]된 BEiT[18]·DeiT[19] 인코더가 고정 크기 입력과 고정 길이 위치 임베딩[27]을 쓰기 때문으로 볼 수 있습니다. 학습 데이터 전체가 같은 방식으로 늘어나서 모델이 그 모양에 적응합니다.
  • CTC[14] 방식과 무엇이 다른가요?
  • CTC는 열마다 문자를 따로 예측하고 합칩니다. TrOCR 디코더는 앞에서 쓴 토큰을 조건으로 다음 토큰을 예측하기 때문에, 언어 지식이 예측 안에 들어갑니다.
  • 왜 외부 언어모델[13]이 필요 없나요?
  • 디코더를 RoBERTa[22]나 MiniLM[23]으로 초기화해서, 텍스트로 사전학습한 언어 지식을 처음부터 갖고 있기 때문입니다.
  • 시험지 전체 사진을 넣으면 읽을 수 있나요?
  • 아니요. 한 줄로 잘라 낸 이미지를 입력으로 받습니다. 시험지 전체를 읽으려면 글자 위치를 찾는 검출 모델이 앞에 필요합니다.
  • 한국어도 읽을 수 있나요?
  • 공개 모델은 영어 데이터와 영어 토크나이저로 학습돼 있어서 바로는 어렵습니다. 한국어 데이터와 토크나이저로 다시 학습해야 합니다.
  • 화면의 확률과 Attention은 실제 모델 값인가요?
  • 아니요. 8·9·13번의 확률과 연결선은 설명용 개념도이고 화면에 그렇게 표시했습니다. 실제 값은 15번 이후의 논문 수치와 18·19번 실험 결과입니다.
  • 빔 서치[30]는 왜 쓰나요?
  • 매번 가장 높은 토큰 하나만 고르면 초반 실수를 되돌릴 수 없습니다. 후보 여러 개를 동시에 유지하다가 전체 확률이 가장 높은 문장을 고릅니다. 논문은 빔 크기 10을 씁니다.
  • TrOCR-Large가 IAM[34]에서 최고라고 할 수 있나요?
  • 표의 최저값은 Diaz et al. 2.75%지만 비공개 내부 데이터와 외부 언어모델을 썼습니다. 합성 데이터[4]와 IAM만 쓴 조건에서는 TrOCR-Large 2.89%가 가장 낮습니다.
  • 15번 그래프의 단계별 차이가 각 기법의 효과인가요?
  • 아닙니다. 앞 단계를 모두 포함한 누적 결과라서, 예를 들어 데이터 증강[12]만의 효과로 9.55를 해석할 수 없습니다. 순서를 바꾸면 차이도 달라질 수 있습니다.
  • 자체 실험에 small-printed 모델을 쓴 이유는?
  • 가장 작은 공개 모델이라 CPU로도 돌릴 수 있고, 실험 이미지가 인쇄체라서 인쇄체용 모델을 골랐습니다. 손글씨는 trocr-base-handwritten 같은 손글씨용 모델이 따로 있습니다.
  • 자체 실험 결과로 TrOCR가 Tesseract[38]보다 낫다고 할 수 있나요?
  • 아니요. 합성 이미지 8장과 같은 문장의 변형 15장이라 표본이 작고 독립적이지 않습니다. 이 조건에서의 경향만 보여 줍니다.
  • Transformer[2]가 CNN[6]보다 항상 좋은가요?
  • 이 논문의 Table 1 조건, 즉 SROIE[31]만으로 학습한 비교에서는 사전학습된 BEiT가 ResNet50보다 높았습니다. 일반적인 결론으로 넓히지는 않습니다.
